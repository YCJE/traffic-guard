# traffic-guard 🚦

**VPS 流量守护** —— 按服务商计费口径监控流量，达到阈值自动预警、自动关机，防止超出流量额度被扣费。

> 适用场景：你的 VPS 流量按「上行/下行取最大值」（或仅上行、仅下行、双向总和）计费，超出额度（如 200G）就要扣钱。装上它，到量自动停机止损。

## 功能特性

- **一键安装**：`bash <(curl -fsSL ...)` 一条命令完成下载、安装并进入配置向导
- **四种计费口径**：上下行取最大值 / 仅上行 / 仅下行 / 双向总和，安装时选择
- **周期自动推算**：自定义每月重置日（1-31 号，29/30/31 在小月自动按月末处理），跨周期自动清零
- **重启不丢计数**：优先使用 vnstat 持久化统计；无法安装时自动降级为 `/proc/net/dev` + 状态文件方案（通过 boot_id 检测重启并累计）
- **两级阈值**：预警阈值（推送提醒，每日最多一次）+ 触发阈值（自动关机，通知先行）
- **多种通知渠道**：Telegram Bot / Server酱（微信）/ Bark（iOS）/ 企业微信 / 钉钉 / 飞书 / 自定义命令，可不通知；Telegram 支持反代地址，国内服务器也能收
- **管理菜单**：安装后输入 `traffic-guard` 弹出交互式菜单（x-ui 风格），查看状态、启停监控、编辑配置一站搞定
- **在线升级**：`traffic-guard upgrade` 从 GitHub 拉取最新版自动替换，配置与统计数据保留
- **演练模式**：`check --dry-run` 完整走一遍检查逻辑但不真的关机

## 快速开始

在 VPS 上以 root 执行**一条命令**即可完成下载与安装：

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/YCJE/traffic-guard/main/install.sh)
```

> 没有 curl 就把 `curl -fsSL` 换成 `wget -qO-`。向导需要交互输入，请直接在 SSH 终端运行。

**手动安装（备选）**：如果偏好先看脚本再执行：

```bash
curl -fsSL https://raw.githubusercontent.com/YCJE/traffic-guard/main/traffic-guard.sh -o traffic-guard.sh
chmod +x traffic-guard.sh
sudo ./traffic-guard.sh install
```

向导会依次询问：

| 问题 | 默认值 | 说明 |
|---|---|---|
| 监控网卡 | 自动探测 | 默认路由网卡；填 `ALL` 统计所有非 lo 网卡 |
| 流量上限 (GB) | 200 | 服务商给的月流量额度 |
| 计费口径 | 上下行取最大值 | 按你的计费规则选择 |
| 安全缓冲 (GB) | 10 | 触发阈值 = 上限 − 缓冲，留出统计口径误差余量 |
| 预警阈值 (GB) | 上限 − 缓冲 − 30 | 达到后推送提醒；0 = 不预警 |
| 每月重置日 | 1 | 服务商流量统计的清零日，控制台/账单页可查 |
| 本周期已用 (GB) | 0 | 安装时周期已过半务必填写，否则会少统计 |
| 检查间隔 (秒) | 60 | systemd 生效；cron 模式固定 60 秒 |
| 通知方式 | 不通知 | 按需选择并填入 token/key，装完自动发测试消息 |

安装完成后，主脚本位于 `/usr/local/bin/traffic-guard`，配置写入 `/etc/traffic-guard.conf`（权限 600），定时任务自动注册（systemd timer 优先，无 systemd 退回 cron，每 60 秒检查一次）。以后随时输入 `traffic-guard` 进入管理菜单。

## 命令一览

| 命令 | 作用 |
|---|---|
| `traffic-guard` | 打开交互式管理菜单 |
| `traffic-guard install` | 交互式安装 / 重新配置 |
| `traffic-guard status` | 查看当前周期用量、阈值、剩余额度 |
| `traffic-guard check` | 执行检查（由定时任务自动调用） |
| `traffic-guard check --dry-run` | 演练检查：只记录日志，不通知不关机 |
| `traffic-guard test-notify` | 发送测试通知 |
| `traffic-guard upgrade` | 在线升级到 GitHub 最新版（配置与数据保留） |
| `traffic-guard uninstall` | 卸载定时任务与脚本（配置保留） |

## 工作原理

1. **统计**：从本周期起始日开始，累计每天的上下行字节数。
   - *vnstat 后端*：vnstat 守护进程把流量持久化到本地数据库，重启不丢，通过 `--json` 按日期区间查询；
   - *proc 后端*：读 `/proc/net/dev` 内核计数器 + 持久状态文件，利用 boot_id 与计数器回退检测重启，把旧值累加回来。
2. **口径计算**：得到周期内 rx / tx 后，按所选口径算用量：取最大值 = `max(rx, tx)`，双向 = `rx + tx`，其余取单项；再加上安装时填写的初始已用量（仅对当前周期生效）。
3. **判断**：用量 ≥ 触发阈值 → 发送「即将关机」通知 → 等 3 秒确保送达 → 自动关机；用量 ≥ 预警阈值 → 每日最多一次预警通知。
4. **调度**：systemd timer 每 60 秒触发一次 `check`（开机自启）；关机后手动重启，同一周期内继续累计，跨过重置日自动归零。

> 单位说明：脚本按 **1 GB = 10⁹ 字节**（十进制）计算，与服务商计费口径一致并略偏保守——即使服务商按 1024 进制计费，也只会提前关机，不会超额。

## 常见问题

**Q: 服务商面板显示的用量和 `status` 不一样？**

服务商在边缘节点统计，通常略高于系统统计，这正是留「安全缓冲」的原因。跑一两天对比一下：面板明显更高就把 `BUFFER_GB` 调大（编辑 `/etc/traffic-guard.conf` 或重跑 `install`）。

**Q: 如何升级到新版本？**

输入 `traffic-guard` 选菜单 8，或直接 `traffic-guard upgrade`。脚本从 GitHub 拉取最新版并校验语法后替换，配置文件、统计数据和定时任务全部保留。自建镜像可设置环境变量 `TG_RAW_URL` 指向你的下载地址。

**Q: 国内服务器收不到 Telegram 推送？**

安装向导选 Telegram 后，把「TG API 地址」填为你的反代地址（如 `https://tg.xxx.com`），脚本会改走该地址发消息；也可以事后编辑配置文件的 `TG_API_BASE`。

**Q: 钉钉机器人一直发送失败？**

钉钉群机器人要求安全设置三选一：自定义关键词（建议填 `traffic`，脚本消息都含 traffic-guard 字样）、加签（把 SEC 开头的密钥填入向导，需系统有 openssl，一般都自带）、IP 白名单。

**Q: 被自动关机后怎么办？**

确认流量情况后手动开机即可。同一计费周期内脚本会继续累计，不会因重启清零；跨过重置日自动重新计数。

**Q: 我的端口是 2.5G / 10G 大带宽，来得及关吗？**

千兆带宽跑满 1 分钟约 7.5G，10G 缓冲足够覆盖 60 秒检查间隔。大带宽端口建议把缓冲调大到 20-30G，或把 `CHECK_INTERVAL` 调到 30 秒（仅 systemd 生效）。

**Q: 刚装完 status 显示 0？**

vnstat 后端从安装时刻开始统计，首次写入数据库需要几分钟（默认保存间隔最长约 5 分钟），期间用量显示 0 属正常，状态里会有一行「⚠ 注意」说明。已有的历史流量靠「本周期已用」初始值补齐；填 0 且周期已过半的话，重跑 `traffic-guard install` 重新填写即可（初始用量只对安装时的周期生效，直接手改配置不生效）。若注意栏提示网卡未加入数据库，执行 `sudo vnstat --add -i 网卡名` 即可。

**Q: 关机会丢数据吗？**

关机走的是正常 poweroff 流程（systemd 优雅关机），和手动 `shutdown` 一样，不会强制断电。

**Q: 如何彻底卸载？**

`traffic-guard uninstall` 移除定时任务和脚本；配置在 `/etc/traffic-guard.conf`、数据在 `/var/lib/traffic-guard`，确认不再使用可手动删除。
